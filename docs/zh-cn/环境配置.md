# PaperReader 环境配置与编译指南

本文档介绍如何在 macOS 和 Windows 上配置开发环境，并从源码编译桌面应用。GitHub Actions 发布流程、Release 标签约定与详细问题排查见[开发者文档](../DEVELOPMENT.md)。

## 一键脚本

仓库提供一键脚本，自动完成下文第 3–5 节的全部配置（Python 3.11 环境、Node.js 检查、构建依赖、前端依赖、`.env`、standalone 翻译运行时），已就绪的步骤自动跳过，可重复执行：

```bash
# macOS（Apple Silicon）
./scripts/setup_build_env.sh            # 只配置环境
./scripts/setup_build_env.sh --build    # 配置环境后直接编译出 .app + .dmg
```

```powershell
# Windows（x64）
powershell -ExecutionPolicy Bypass -File .\scripts\setup_build_env.ps1           # 只配置环境
powershell -ExecutionPolicy Bypass -File .\scripts\setup_build_env.ps1 -Build    # 配置环境后直接编译出 ZIP
```

首次运行前仍需手动准备的只有：macOS 的 Xcode Command Line Tools 与 conda/Homebrew 之一；Windows 的 Git 与 winget（缺失时脚本会给出安装提示）。脚本会自动下载 python-build-standalone 并安装 worker 依赖，体积较大，首次配置需要一些时间。下文各节为手动分步说明，便于单独排错。

## 1. 技术栈与构建方式

| 部分 | 技术 | 打包工具 / 产物 |
| --- | --- | --- |
| 前端 | React + TypeScript + Vite | 构建为 `frontend/dist` 静态资源 |
| 后端 | FastAPI + Uvicorn | 随应用一起打包 |
| 原生窗口 | pywebview（macOS 用 WKWebView，Windows 用 WebView2） | — |
| macOS 打包 | py2app | `desktop/build_macos.sh` → `.app` + `.dmg` |
| Windows 打包 | PyInstaller | `desktop/build_portable.ps1` → 可移植 ZIP |
| 翻译 worker | PDFMathTranslate-next（独立 Python 运行时） | 以 `worker-runtime` 目录随包发布 |

产物版本号取自 `frontend/package.json` 的 `version`。

## 2. 环境要求

### macOS

- Apple Silicon Mac（arm64），macOS 13 或更高
- Git、Xcode Command Line Tools（`xcode-select --install`）
- Python 3.11（arm64 原生）
- Node.js 20 + npm

### Windows

- Windows 10/11 64 位（x64）
- Git for Windows（自带 Git Bash；下文命令默认在 Git Bash 中执行）
- Python 3.11（x64，安装时勾选 "Add python.exe to PATH"）
- Node.js 20 + npm
- Microsoft WebView2 Runtime（Windows 10/11 一般已内置）

检查环境：

```bash
uname -m            # macOS 应输出 arm64
python --version    # 3.11.x
node --version      # v20.x
```

## 3. 通用环境配置

### 3.1 获取源码

```bash
git clone https://github.com/Mars-Dingdang/PaperReader.git
cd PaperReader
```

### 3.2 Python 环境

项目约定使用 conda 环境 `pt`（`scripts/setup_macos.sh` 亦使用该环境）：

```bash
conda create -n pt python=3.11 -y
conda activate pt
```

或用 venv。macOS：

```bash
python3.11 -m venv .venv
source .venv/bin/activate
```

Windows（Git Bash 的激活脚本在 `Scripts` 下）：

```bash
python -m venv .venv
source .venv/Scripts/activate
```

安装构建依赖（包含后端依赖、pywebview，以及 py2app / PyInstaller 等平台打包工具）：

```bash
python -m pip install --upgrade pip
python -m pip install -r desktop/requirements-build.txt
```

### 3.3 前端依赖

```bash
npm --prefix frontend ci
```

仅当 lockfile 与 `frontend/package.json` 不一致时才用 `npm --prefix frontend install` 重新生成，并把 `frontend/package-lock.json` 一并提交。

### 3.4 配置文件

```bash
cp .env.example .env
```

按需填写 `OPENAI_API_KEY` / `OPENAI_BASE_URL` / `OPENAI_MODEL`，并把 `PDFMATHTRANSLATE_PYTHON` 指向装有 worker 依赖的解释器（见下节）。只做 Web 联调（不打包桌面应用）时，也可以用 `scripts/setup_macos.sh` / `scripts/setup_windows.ps1` 一键完成这节的依赖安装。

## 4. 翻译 worker 运行时

翻译由独立进程 `workers/pdfmathtranslate` 完成。它的依赖（ONNX、OpenCV、scikit-image、HuggingFace Hub 等）只装在它自己的运行时里，与后端环境隔离，清单见 `desktop/requirements-worker.txt`（pdf2zh-next、babeldoc、scipy>=1.16）。运行时要求 Python 3.10–3.13；macOS 上请用 3.11+，旧版 scipy 在新系统上无法加载。

### 4.1 开发用运行时（venv 即可）

macOS：

```bash
python3.11 -m venv worker-runtime
worker-runtime/bin/pip install -r desktop/requirements-worker.txt
```

Windows（Git Bash）：

```bash
python -m venv worker-runtime
worker-runtime/Scripts/pip install -r desktop/requirements-worker.txt
```

在 `.env` 中把 `PDFMATHTRANSLATE_PYTHON` 指向它。写成 `worker-runtime/bin/python3`（Windows：`worker-runtime/Scripts/python.exe`）这类相对路径时按仓库根目录解析，裸名字（如 `python3`）才按 `PATH` 查找。`desktop/launcher.py` 还会自动探测仓库根目录下的 `worker-runtime/`。

### 4.2 发布用运行时（必须 standalone）

正式打包时 `desktop/worker-runtime` 会被整体复制进安装包，因此它不能是 venv，必须满足以下全部条件，两个打包脚本都会逐项校验，不满足会直接失败：

- 使用 python-build-standalone 这类 standalone Python 发行版（解压即用、不依赖绝对路径）；
- 已按 `desktop/requirements-worker.txt` 安装全部依赖；
- 根目录有 `runtime-manifest.json`，内容为 `{"runtime_type": "python-standalone"}`；
- 其中的解释器能成功执行 `import pdf2zh_next, babeldoc`。

准备步骤（以 python-build-standalone 为例）：

```bash
# 1. 从 astral-sh/python-build-standalone 下载 cpython-3.11 的 install_only 包
#    （macOS 选 aarch64-apple-darwin，Windows 选 x86_64-pc-windows-msvc）
# 2. 解压到 desktop/worker-runtime

# 3. 安装 worker 依赖（Windows 解释器在 desktop\worker-runtime\python.exe）
desktop/worker-runtime/bin/python3 -m pip install -r desktop/requirements-worker.txt

# 4. 写入 manifest
echo '{"runtime_type": "python-standalone"}' > desktop/worker-runtime/runtime-manifest.json

# 5. 自检
desktop/worker-runtime/bin/python3 -c "import pdf2zh_next, babeldoc"
```

## 5. macOS 编译

### 5.1 从源码直接运行（调试用）

```bash
npm --prefix frontend run build
python desktop/launcher.py
```

启动器会在 `127.0.0.1:8000` 启动内嵌后端，并用 WKWebView 打开原生窗口。它读取的是已构建好的 `frontend/dist`，修改前端后需重新执行 `npm --prefix frontend run build` 才会进入原生窗口。

应用数据在 `~/Library/Application Support/PaperReader/`，启动异常查看其中的 `PaperReader-error.log`。端口 8000 被占用时，用 `lsof -nP -iTCP:8000 -sTCP:LISTEN` 找到旧进程并结束后重试。

### 5.2 构建 .app + .dmg

构建前先确认当前 `python` 就是要用来打包的 3.11 arm64 解释器——脚本以它推导 bundle 内的版本目录（`Resources/lib/python3.11`）并补拷运行时库：

```bash
python -V
./desktop/build_macos.sh
```

脚本依次执行：`npm ci` → `npm run build` → 生成 `.icns` → py2app 构建 `.app` → 补拷运行时 Python 包与动态库 → 把 `desktop/worker-runtime` 复制到 `Contents/Resources/worker-runtime`（签名之前，保证签名覆盖）→ ad-hoc `codesign` → `hdiutil` 生成压缩 DMG → 写 SHA-256。

输出（版本号取自 `frontend/package.json`）：

```text
dist/PaperReader.app
release/PaperReader-v<version>-macOS-arm64.dmg
release/PaperReader-v<version>-macOS-arm64.dmg.sha256
```

直接验证：

```bash
open dist/PaperReader.app
```

当前发布使用 ad-hoc 签名、未做 Apple 公证：其他 Mac 首次打开被 Gatekeeper 拦截时，在 Finder 中 Control-click（或右键）选择「打开」即可。

## 6. Windows 编译

### 6.1 从源码直接运行

```bash
npm --prefix frontend run build
python desktop/launcher.py
```

应用数据在 `%LOCALAPPDATA%\PaperReader\`（Git Bash 下即 `~/AppData/Local/PaperReader/`），启动异常查看其中的 `PaperReader-error.log`。

### 6.2 构建可移植 ZIP

```bash
powershell -ExecutionPolicy Bypass -File ./desktop/build_portable.ps1
```

`python` 或 `npm` 不在 PATH 时显式指定：

```bash
powershell -ExecutionPolicy Bypass -File ./desktop/build_portable.ps1 \
  -PythonPath "C:/Python311/python.exe" \
  -NpmPath "C:/Program Files/nodejs/npm.cmd"
```

脚本依次执行：`npm ci` → `npm run build` → PyInstaller 按 `desktop/PaperReader.spec` 打包 `PaperReader.exe`（并打入 `workers/` 包）→ 把 `desktop\worker-runtime` 复制为包内 `worker-runtime` → 附入使用说明与 `create_shortcut.ps1` → 压缩 ZIP 并写 SHA-256。构建开始前会自动结束正在运行的 PaperReader 进程，避免文件被占用。

输出：

```text
dist/PaperReader/PaperReader.exe
release/PaperReader-v<version>-Windows-x64.zip
release/PaperReader-v<version>-Windows-x64.zip.sha256
```

EXE 未做 Authenticode 签名；最终用户解压整个 ZIP 后运行 `PaperReader.exe`，无需安装 Python 或 Node.js。

## 7. 构建后验证

```bash
# 后端测试与语法检查（两平台相同）
python -m pytest backend/tests -q
python -m compileall -q backend/app

# macOS：签名与冒烟检查、校验 DMG
codesign --verify --deep --strict dist/PaperReader.app
python scripts/smoke_release.py --app dist/PaperReader.app
shasum -a 256 release/PaperReader-v*-macOS-arm64.dmg

# Windows（Git Bash 自带 sha256sum）
python scripts/smoke_release.py --web
python scripts/smoke_release.py --archive release/PaperReader-v*-Windows-x64.zip
sha256sum release/PaperReader-v*-Windows-x64.zip
```

## 8. 常见问题

- **`npm ci` 报 lockfile 与 `package.json` 不一致**：执行 `npm --prefix frontend install` 后提交更新过的 `frontend/package-lock.json`。
- **py2app 构建失败**：确认 `python --version` 为 3.11 且 `python -c "import platform; print(platform.machine())"` 输出 arm64；构建日志在 `build/macos-py2app.log`。
- **`.app` / `.exe` 启动即退出**：查看错误日志（macOS `~/Library/Application Support/PaperReader/PaperReader-error.log`；Windows `%LOCALAPPDATA%\PaperReader\PaperReader-error.log`），常见原因是 8000 端口被旧进程占用。
- **上传返回 `worker_unavailable`**：`PDFMATHTRANSLATE_PYTHON` 指向的解释器不存在或不可执行。能上传但翻译失败时，用该解释器执行 `python -c "import pdf2zh_next, babeldoc"` 自检依赖是否装齐；打包版本再确认 `worker-runtime` 已随包复制（macOS 在 `.app/Contents/Resources/worker-runtime`，Windows 在包根目录）。
- **macOS 首次打开提示「无法验证开发者」**：ad-hoc 签名未公证所致，Control-click →「打开」绕过；需要免警告分发则要引入 Developer ID 签名与 notarization（当前未集成进构建脚本）。
- **Windows 打包版窗口空白或无法启动**：确认系统已安装 Microsoft WebView2 Runtime。
- **重新干净构建**：删除 `build/`、`dist/`、`frontend/dist/` 后重跑打包脚本；`desktop/worker-runtime` 不是构建产物，不需要清理。
