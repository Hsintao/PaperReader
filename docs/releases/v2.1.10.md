# PaperReader v2.1.10

> 📖 **Read the [User Guide (中文)](https://github.com/Mars-Dingdang/PaperReader/blob/main/docs/user_instruction.md) before downloading** — installation, first-run setup, and usage. [中文发布说明](https://github.com/Mars-Dingdang/PaperReader/blob/main/docs/zh-cn/releases/v2.1.10.md)

PaperReader v2.1.10 improves the completion rate of automatic LaTeX recovery. A compile failure is now treated as an iterative repair problem: the model receives the latest compiler result after every attempt and can continue until the translated document compiles or the five-round limit is reached.

## What's new

- **Missing error windows no longer stop recovery.** A log without a usable `l.<n>` or file-line anchor still reaches diagnosis with the compiler failure and current TeX source.
- **Compiler feedback drives the next attempt.** The initial compile error, diagnosis, applied patches, rejected response details, and later compiler errors are carried into subsequent rounds.
- **The repair scope matches real LaTeX causes.** Repairs may update preamble definitions, add an ordinary package declaration, correct macros, or replace a complete broken environment. The previous narrow control-sequence allowlist and two-round limit are removed.
- **Source content remains accounted for.** Patches use exact complete source lines, reject new file and shell access, limit the total edit size, and refuse large content deletion. A before-repair copy is saved for every applied round without overwriting earlier backups.
- **Model response handling is more tolerant.** Strict JSON may be returned inside a Markdown JSON fence, and malformed or rejected output is reported back for another attempt.

## Compatibility

This is a backward-compatible release. Existing `DATA_DIR`, SQLite databases, account settings, provider credentials, TeX projects, and completed translation checkpoints remain usable. No manual database migration is required. Translated PDF generation still requires TeX Live with `latexmk` and the selected TeX engine.
